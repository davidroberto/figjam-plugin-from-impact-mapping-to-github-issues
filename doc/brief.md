CONTEXTE PRODUIT

Le produit est un outil d’accompagnement des ateliers produit (impact mapping, user story mapping, example mapping) réalisé dans FigJam.

Il a deux rôles principaux :
1.	Aider à clarifier et challenger les zones de flou pendant les ateliers
2.	Transformer un atelier validé en backlog GitHub actionnable

L’outil s’appuie sur :
•	une modélisation stricte (arbre, 1 parent par élément)
•	des conventions visuelles (shapes, couleurs, flèches, sections)
•	une analyse globale du contexte
•	une synchronisation automatisée vers GitHub

OBJECTIF MÉTIER 1

Clarifier et challenger les zones d’ombre pendant les ateliers

⸻

ACTEUR

Product Owner

⸻

OBJECTIF ACTEUR

Identifier et rendre explicites les zones de flou pendant l’atelier

⸻

ACTIONS
•	Analyser l’impact mapping, le user story mapping et l’example mapping dans leur globalité
•	Reconstruire la hiérarchie métier complète à partir des flèches
•	Détecter les incohérences entre objectifs, impacts, actions et user stories
•	Challenger la formulation des user stories dans leur contexte
•	Identifier les règles métier, UI et système ambiguës ou implicites
•	Évaluer la couverture des scénarios associés aux règles
•	Mettre en évidence les zones non couvertes ou contradictoires
•	Restituer les zones de flou directement dans FigJam

⸻

OBJECTIF MÉTIER 2

Préparer un backlog GitHub clair et actionnable pour le sprint

⸻

ACTEUR

Product Owner

⸻

OBJECTIF ACTEUR

Transformer un atelier FigJam validé en backlog GitHub sans ressaisie

⸻

ACTIONS
•	Analyser les éléments FigJam validés (objectifs, acteurs, impacts, actions, user stories, règles, scénarios)
•	Reconstruire une hiérarchie stricte (1 parent par élément)
•	Créer une GitHub issue pour chaque élément FigJam
•	Conserver la hiérarchie parent → enfant dans GitHub
•	Ajouter toutes les issues au GitHub Project
•	Positionner chaque issue dans la colonne correspondant à son type
•	Associer les user stories, règles et scénarios à la bonne release
•	Éviter les doublons lors des synchronisations successives
•	Mettre à jour les issues existantes si l’atelier évolue
